# 跑步环境影响分析

使用环境数据解释配速、心率、步频、体感和训练负荷为什么偏离纯体能预期。天气具有时效性；给真实训练建议时必须尽量获取当前或预报数据，不要用过期或想象的天气下结论。

## 需要匹配的数据

分析已完成跑步或规划未来训练时，尽量覆盖：

- 活动日期和开始时间。
- 地点名称和起点坐标。
- 温度。
- 相对湿度。
- 露点或体感温度。
- 风速和风向。
- 降水概率和雨量。
- 日照或云量。
- 用户要求时加入空气质量（AQI）。
- 活动详情中的地形/爬升。

## 当前和未来训练

天气获取优先顺序：

1. 使用当前 agent 可用的天气工具查询计划地点和时间窗口。
2. 若只有城市级天气，标记置信度为 `中`。
3. 若只有季节或用户背景，标记置信度为 `低`，只给条件式建议。

## 历史活动天气

历史活动需要匹配活动开始时间、地点或坐标。可用历史天气源时，优先匹配小时级数据。若当前工具环境没有历史天气 API，不要编造数值。

## 热应激等级

优先用露点和体感温度；没有露点时用温度 + 湿度。

- `低`：气温 < 22 C，湿度 < 70%，露点 < 16 C。
- `中`：气温 22-26 C，或湿度 70-75%，或露点 16-18 C。
- `高`：气温 > 26 C，或湿度 > 75%，或露点 > 18 C，或体感明显高于气温。
- `很高`：高温高湿叠加直晒、低风或长距离/质量课。

热应激高时：

- 轻松跑用体感或心率，而不是固定配速。
- 降低间歇/阈值/马配目标，或延长恢复、减少组数；马配段改为努力感或心率上限。
- 长距离改为时间制或缩短。
- 增加补水、电解质和降温策略。
- 不把热影响导致的配速下降直接判断为体能下降。

## 时间段

- 晨跑通常热应激更低，相同配速下心率可能更低。
- 中午或下午跑可能有更高热负荷、脱水风险和更高心率。
- 夜跑可能受全天疲劳、进食和咖啡因影响。

时间段未知时，不要下强结论，只能把地点、日期和用户背景当作弱证据。

## 风和雨

- 逆风会降低配速并提高用力。
- 顺风可能掩盖真实强度。
- 雨能降温，但会增加路面风险。
- 强风或大雨时，把建议从配速目标改为体感和安全。

## 温度修正

马拉松和长距离对温度非常敏感。PLOS ONE 对大型马拉松数据的研究显示，气温是影响全马表现的重要因素，温度上升会降低速度并提高退赛率。用作背景，不机械套用。

- 凉爽干燥：允许配速目标更接近计划。
- 气温、湿度或露点触发热应激阈值时，按上文热应激等级修正。
- 体感温度明显高于气温：按体感温度修正。

## 环境解释规则

- 温暖潮湿时，如果配速变慢且心率更高，先考虑环境负荷、补水和疲劳，再判断体能问题。
- 凉爽干燥时，如果同心率配速更快，要说明天气可能帮助表现，不要直接判定体能大幅提升；比赛预测仍要结合路线、风、补给和起跑拥挤。
- 只在地形和天气大致相近时比较相似跑步。
- 最终回答要区分"体能信号"和"环境信号"。

旅行或城市变化时：

- 先考虑睡眠、饮食、出差疲劳、气候差异和路线陌生。
- 不同城市活动不要直接用平均配速横向比较。

## 输出要求

```text
环境：
- 时间/地点：
- 天气来源：
- 热应激：
- 可能影响：
- 置信度：
- 缺失项：
```

置信度标签：

- `高`：精确活动时间/地点匹配到小时级天气。
- `中`：同城同日，时间近似（或只有城市级预报）。
- `低`：天气不可用，或仅从季节/背景推断。

相关文档：高温下的补水与电解质见 `fueling.md`；比赛期温度背景见 `marathon-framework.md`。
