# 数据质量与置信度

先判断数据是否足以支撑结论，再给训练建议。数据不足时不要填补或编造。

## 覆盖度评分

按任务给 `高 / 中 / 低`：

- `高`：核心数据齐全且新鲜。今日建议至少有最近 7 天睡眠、HRV、静息心率、恢复、训练负荷和近期运动；周复盘至少有 14 天运动和关键活动详情；比赛计划至少有 60-90 天运动和近 30 天负荷。
- `中`：缺少 1-2 个关键项，但仍有足够交叉信号。例如缺压力但有睡眠、HRV、RHR 和训练负荷。
- `低`：缺少多个核心项、数据超过任务窗口、只有活动列表没有恢复数据，或只有单一指标。

输出必须写清：

```text
数据置信度：
- 等级：
- 覆盖：
- 缺失：
- 对结论影响：
```

## 时效性

- 今日建议：恢复、睡眠、HRV、RHR 应优先使用最近 24-36 小时；没有今日数据时标记过期。
- 周复盘：以最近 7-14 天为主，允许 28-42 天作为基线。
- 比赛计划：用 60-90 天训练史判断基础，用最近 7 天判断今日能否执行。
- 天气和预报具有时效性；真实训练建议要尽量查询当前或预报来源。

## 来源优先级

1. COROS MCP 原始工具结果。
2. `coros-mcp call-tool` CLI 兜底结果。
3. 用户提供的导出或截图。
4. 用户文字描述。

用户描述可以补充主观疲劳、疼痛、胃肠、补给和时间安排，但不要覆盖明确的生理数据；当二者冲突时说明冲突。

## 缺失数据处理

- 缺睡眠/HRV/RHR：不要安排高强度，只能给轻松跑、恢复跑或条件式建议。
- 缺训练负荷：用最近活动频率、时长、长距离和质量课密度替代，并降低置信度。
- 缺圈速：单次活动只能基于总览分析，不判断后半程漂移或间歇稳定性。
- 缺天气：只给条件式环境解释，不给具体温度修正。
- 缺目标赛事信息：给当前能力画像和 4 周建设块，不假装完整周期已确定。

## 结论强度

- 数据齐全且信号一致：使用“建议”。
- 数据部分缺失或信号混合：使用“倾向于”。
- 数据不足但必须给行动：使用“保守选项”。
